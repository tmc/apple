# e5rtstack

Runs a stack of transformer blocks on the Neural Engine through the private
`e5rt` direct-dispatch route, and checks the result against a float64 CPU
reference of the whole stack.

`e5rtblock` runs one block and closes its second residual on the host. This runs
many, and closes everything on the device: the host writes the input once, calls
execute, and reads the output once, whatever the depth.

```sh
go run ./examples/ane/e5rtstack
go run ./examples/ane/e5rtstack -layers 16
go run ./examples/ane/e5rtstack -layers 6 -dim 128 -heads 8 -seq 32 -hidden 256
```

## Three programs per layer

`GenSDPAForward` ends in `add(x, projection)`, so it carries the first residual
itself. `GenFFNForwardRMSReLU2` carries neither, so the second residual is a
program of its own — a two-input elementwise add, generated by `genAdd` — whose
output buffer is the next layer's input buffer. Doing that add on the host
instead would put a read and a write between every pair of layers.

Nothing is copied between layers. One buffer object is bound to the attention
program's output port and to the feed forward program's input port, and the host
never sees an intermediate activation.

## What this found: fifteen live operations

**A process can hold fifteen precompiled compute operations at once. The
sixteenth fails with status 13.**

This is not the known weight-file ceiling. It counts operations, not weights: a
trivial weightless `add` program hits it identically, while compiling that same
program and retaining its function forty times over raises no complaint. Only
`e5rt_execution_stream_operation_create_precompiled_compute_operation_with_options`
is limited.

Three follow-up measurements pin down the shape of it:

| action | result |
| --- | --- |
| create 40 operations | fails at the 16th |
| compile + retain 40 functions, create none | all 40 succeed |
| create, release, repeat 40 times | all 40 succeed |
| create, **encode**, release, repeat | fails at the 16th |
| execute and release the stream every 12 | all 40 succeed |

So the slot belongs to the live operation, releasing an operation returns it,
and an encoded operation is held by its stream — which makes releasing the
stream the only way to get the slots back.

The pool is shared between processes rather than reserved per process. Two
copies of this program running concurrently reproducibly get 15 and 7.

### Going deeper than five layers

Each layer is three operations, so fifteen caps a single stream at five layers.
Deeper stacks run in phases: encode what fits, execute, release the stream,
encode the next group. Buffers are allocated once and stay bound across the
boundary, so phases hand activations to each other in place. **A phase boundary
costs an encode, not a copy and not a host round trip.** Sixteen layers run this
way, matching the reference to a worst difference of 0.0051 against a peak of
2.21.

The cost of the boundary is visible in the timings: a stack that fits in one
phase keeps its stream encoded and re-executes in 413µs per layer, while the
first dispatch — which includes the encode — takes 53ms for the same four
layers.

### Encode order is execution order

The stream runs operations in the order they were encoded and does not reorder
them to satisfy a dependency. Encoding a layer's residual add before the feed
forward it reads produces a stale result rather than an error; see mutation M2
below.

## Why the weight file ceiling does not bite here

One attention program needs six weight files and one feed forward program needs
three. Nine per layer, against a compiler that stops accepting weight files at
sixteen — so a stack that put every layer's weights in one directory would fail
to compile at two layers. It compiles here because each program is compiled
separately from its own directory, which is what makes that ceiling a
per-compile limit rather than a limit on model size. Packing many tensors into
one file is the other way around it; see `x/ane/mil`'s `BlobWriter`.

## Controls

Depth is what this example adds over `e5rtblock`, so it checks that the depth is
real. Every layer's attention scores must have enough spread that the softmax
selects rather than averages — an attention that averages is reproduced exactly
by a wrong head split and by a missing causal mask, which is how the first
version of `e5rtblock` passed while verifying nothing. And the N-layer result
must differ from the (N-1)-layer result by more than the comparison tolerance,
or a stack that silently dropped its last layer would pass just as well.

The compiled bundle is read for which backend the compiler actually chose, since
the device mask is a permission and not a placement and a stack that fell back
to the CPU would return the same correct answer. One input element is then
perturbed and the stack re-dispatched, which must move the output and must still
match a reference recomputed from the perturbed input.

Residual peak is printed per layer. Everything on the engine is fp16, and a
residual stream that grows geometrically with depth leaves its range; the
weights here are damped so growth is sublinear (0.80 at layer 1 to 2.21 at layer
16), and a non-finite output is reported as such rather than compared.

Three deliberate mutations were each run against the real engine output and each
was caught:

| mutation | worst \|diff\| |
| --- | --- |
| residual reads the layer input instead of the attention output | 0.6813 |
| residual encoded before the feed forward it reads | 0.6389 |
| last layer bound but never encoded | 1.1650 |

The last is exactly the reference peak, because the output buffer is never
written at all.
